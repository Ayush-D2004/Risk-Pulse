# RiskPulse Data Directory

This directory stores all local datasets, processed outputs, database files, and pipeline artifacts.

## 🚀 Note for Evaluators: How to run the project without large files

RiskPulse is designed to be **runnable right out of the box** without needing to download massive multi-gigabyte datasets! 
The UI dashboard and the live NLP pipelines are completely decoupled from the offline historical data.

1. **Start the backend and frontend:** Follow the instructions in the main repository `README.md`.
2. **Explore the Command Center:** The dashboard will instantly load using the built-in deterministic demo fixtures.
3. **Run Live Pipelines:** You can execute live pipeline runs straight from the UI! Navigate to the **Analyst Simulation** or **Live News Intelligence (GDELT)** workspaces to trigger the NLP engine (FinBERT, DeBERTa-v3, FAISS) on live inputs.

---

### 📥 Optional: Re-running the Offline Historical Pipeline

If you want to manually execute the offline historical data pipeline from the CLI (which processes over 800k historical tweets) or inspect the precomputed outputs, you can download the complete historical archive.

To make this effortless, we have created an automated download script `download_data.py` in the root directory.

#### Automated Setup (Recommended)
Simply run:

```bash
python download_data.py
```

This script:
1. Downloads the package archive directly from Google Drive:
   - **Google Drive Link:** [RiskPulse Historical Data Archive](https://drive.google.com/file/d/1jm-49S-1m6m1u74ll8p_mOl7ooHAtSiP/view?usp=sharing)
2. Displays download progress via `gdown`.
3. Automatically reconstructs the expected repository directory layout:
   - `data/processed/full_dataset-release.csv`
   - `data/processed/reduced_dataset-release.csv`
   - `data/pipeline_output/` (including `canonical_events.csv` and model outputs)
4. Cleans up the temporary zip archive and validates file placement.

#### Manual Setup (Fallback)
If you prefer manual setup:
1. Download the zip archive from [Google Drive](https://drive.google.com/file/d/1jm-49S-1m6m1u74ll8p_mOl7ooHAtSiP/view?usp=sharing).
2. Extract `full_dataset-release.csv` and `reduced_dataset-release.csv` into `data/processed/`.
3. Extract the contents of `pipeline_output/` into `data/pipeline_output/`.

## Folder Structure

- `raw/`: Contains the original, unmodified datasets. 
  - **Twitter Dataset:** [Tweet Sentiment's Impact on Stock Returns (Kaggle)](https://www.kaggle.com/datasets/thedevastator/tweet-sentiment-s-impact-on-stock-returns). Used for simulating historical financial chatter and stress-testing the NLP pipeline.
  - *Note: Raw datasets are large and ignored by version control.*
- `processed/`: Contains intermediate outputs and clean input files:
  - `full_dataset-release.csv` (~235 MB)
  - `reduced_dataset-release.csv` (~23 MB)
- `pipeline_output/`: The final results generated by the RiskPulse NLP Risk Engine (e.g., `canonical_events.csv`, `guard_scored.csv`, `impact_scored.csv`, clustering checkpoints).
- `pipeline_output_dryrun/` & `pipeline_output_test/`: Sandboxed output directories used for unit testing and CI/CD dry-runs so that production/demo data isn't overwritten.

## Database Files
- `riskpulse.db`: The core SQLite database storing configuration and static fixtures (Tracked in Git).
- `riskpulse_runtime.db`: The SQLite database (running in WAL mode) used by the `RuntimeStore` to persist the lifecycle of live `PipelineRuns` from GDELT or Analyst Simulations.
- `*.db-shm` / `*.db-wal`: SQLite Write-Ahead Log shared memory files. These are ephemeral and automatically created by SQLite.

## Usage
To execute the historical pipeline across the dataset:
```bash
python src/pipeline/run_pipeline.py --input data/processed/full_dataset-release.csv --output-dir data/pipeline_output
```
