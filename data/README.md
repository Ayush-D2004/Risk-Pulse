# RiskPulse Data Directory

This directory stores all local datasets, processed outputs, database files, and pipeline artifacts.

## Folder Structure

- `raw/`: Contains the original, unmodified datasets. 
  - **Twitter Dataset:** [Tweet Sentiment's Impact on Stock Returns (Kaggle)](https://www.kaggle.com/datasets/thedevastator/tweet-sentiment-s-impact-on-stock-returns). Used for simulating historical financial chatter and stress-testing the NLP pipeline.
  - *Note: Raw datasets are often too large for version control and should be ignored.*
- `processed/`: Contains intermediate outputs, such as data cleaned for FinBERT inference or split into manageable chunks.
- `pipeline_output/`: The final results generated by the RiskPulse NLP Risk Engine (e.g., Canonical Events, Signals, clustering checkpoints).
- `pipeline_output_dryrun/` & `pipeline_output_test/`: Sandboxed output directories used for unit testing and CI/CD dry-runs so that production/demo data isn't overwritten.

## Database Files
- `riskpulse.db`: The core SQLite database storing configuration and static fixtures.
- `riskpulse_runtime.db`: The SQLite database (running in WAL mode) used by the `RuntimeStore` to persist the lifecycle of live `PipelineRuns` from GDELT or Analyst Simulations.
- `*.db-shm` / `*.db-wal`: SQLite Write-Ahead Log shared memory files. These are ephemeral and automatically created by SQLite.

## Usage
When running `src/pipeline/run_pipeline.py`, ensure your input CSVs are placed in `raw/` or `processed/`, and designate an output directory inside `pipeline_output/`.
