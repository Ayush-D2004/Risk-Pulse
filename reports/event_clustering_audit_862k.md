### Missed Duplicates & False Merges
If Siemens was split into multiple clusters despite being the same event, it's a *missed duplicate*.
If a cluster contains completely unrelated tweets, it's a *false merge*.

## Recommended Minimal Changes
1. **Entity Resolution**: The upstream NER dataset logic frequently captures publishers (e.g., Reuters, CNBC) or usernames (`RT @XYZ`) as the `STOCK` entity. A minimal fix is to blacklist common publisher names in the mapping, or strictly resolve `STOCK` only to known Universe tickers (e.g., AAPL, F, SIE).
2. **Event Clustering constraints**: The existing Event Clusterer requires EXACT match on `entity` and `event_type`. If Siemens is sometimes tagged as 'Siemens' and sometimes as 'Siemens AG', or if the event type fluctuates between 'Geopolitical' and 'Regulatory', they will form separate clusters. Normalization is required.

## Readiness
- **Is Event Clusterer ready for production?**: The core FAISS semantic grouping works well, but it is heavily bottlenecked by upstream entity normalization. Until the entity is canonical (e.g. TICKER instead of raw text), it will falsely split duplicate events because `c.entity != candidate.signal.entity`.
- **Can Market Validation Proceed?**: Yes, provided we run market validation ONLY on the clustered output (taking the canonical earliest signal from each cluster) AND we exclude obvious publisher-named clusters (e.g., Entity='Reuters').
